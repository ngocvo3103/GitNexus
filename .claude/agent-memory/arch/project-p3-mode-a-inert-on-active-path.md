**IMPLEMENTED & verified — issue #166 (2026-06-10).** WI-1 in working tree on `feature/159-lsp-augmented-resolution`; WI-V coverage green; full suite green (223 files / 6360 tests, 0 fail). NOT yet committed (Zero-Auto-Commits). Plan `docs/plans/166-mode-a-wire-active-path.md` (Status: in review) + design `docs/designs/166-mode-a-wire-active-path.md`. Original bug: `analyze --lsp` produced ZERO lsp-augmented edges on any repo using the sequential path (everything under MIN_FILES_FOR_WORKERS=1_000_000 / MIN_BYTES_FOR_WORKERS=1GB).

**Root cause (historical):** LSP candidate feeds (`correctionFeed`/`recallFeed`, pipeline.ts:314-318) were wired via `lspFeedsOpt` only into `processCallsFromExtracted` on the WORKER path (pipeline.ts:383, dormant ≥1M files/1GB) and the Angular-only post-pass (:531). The ACTIVE sequential resolver `processCalls` (call-processor.ts) emits the general CALLS graph but had no `opts` param, so feeds stayed empty → `candidates=[]` → no augmentation. A recurrence of [[project-ingestion-dual-path-gotcha]].

**Fix as implemented (verified in code 2026-06-10):** `processCalls` gained `opts?: ProcessCallsOpts` (final positional). Recall pushes INSIDE the `if(!resolved)` block (call-processor.ts:660-666, push then return); correction pushes inside the `resolved.reason==='global'` guard (:676-685); both gated `if(opts?.lsp && opts.{recall,correction}Feed)`, using `nameNode.startPosition` (callee identifier, already in scope at :461). `pipeline.ts:492` now passes `lspFeedsOpt`. Candidate dedup by `candidateLocationKey` handles the now-two-producer feed. The server-INDEPENDENT feed-population tripwire lives in `test/unit/call-processor.test.ts:799/827/858/891` (default→empty, correction→populated, recall→populated) — hermetic, the regression guard the original blind spot lacked.

**⚠️ B1 REVERSAL — CRITICAL CORRECTION (the code evolved since my earlier note):** in-memory CALLS edges NOW DO stamp `source:'heuristic'` explicitly on the default path — EVERY emit site does it: call-processor.ts:694 (processCalls), :713 (deferred ACCESSES), :1542 (processCallsFromExtracted), route-extracted :1806/:1822/:1835, reconciler mode-a-reconciler.ts:1348. `csv-generator.ts:474`'s serializer-side default is a BACKSTOP, not the primary stamp. Therefore the hard-equality guards `expect(r.source).toBe('heuristic')` at `mode-a-golden.test.ts:370`/`:486` are the load-bearing **B1 contract** — they MUST fail on a missing stamp. **Do NOT coalesce them to `r.source ?? 'heuristic'`** — that is a regression-masking tautology. My earlier memory said "B1 is not a bug / assert effective source / in-memory source is undefined by design" — that was TRUE at #159-planning time but is FALSE on the implemented code. Trust the on-disk emit sites + guards, not the stale design prose. (The #166 issue body "Out of scope" section and design KD-5 carried the same fossil; both corrected 2026-06-10.)
